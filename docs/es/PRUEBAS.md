## Baterías de pruebas

En GitHub, `.github/workflows/tests.yml` se ejecuta en cada envío y pull request, en Linux y Windows (no necesita servidor RDP):

- `tests/run.php` y `tests/fuzz.php --strict` con PHP 8.1, 8.2, 8.3, 8.4 y 8.5; cualquier aviso, notice o deprecación de PHP hace fallar. Una excepción, avisada en la salida: con PHP 8.1 allí, el servidor web integrado de PHP (de desarrollo, solo lo usan las pruebas) se detiene con la petición que agota la memoria antes de enviar ninguna página, así que esa página no se puede comprobar allí; se comprueba con 8.2 a 8.5 allí y con 8.1 en el equipo de pruebas con Windows.
- Todas las `tests/*_unit.mjs` y `tests/fuzz.mjs --strict` con la LTS actual y la anterior de Node.js (Node.js 22 o posterior: las pruebas usan el `navigator` global del navegador, que Node tiene desde la versión 21).
- La imagen Docker, construida y arrancada (solo en Linux): responde por HTTPS con la pantalla de instalación, deja fuera de alcance las carpetas privadas, rechaza un cuerpo de más de 8 MB y no tiene archivos locales; después lo mismo con Docker Compose (`compose.yaml`, con su imagen construida con ese código): la pantalla de instalación, el código de instalación, el volumen de datos y ningún `compose.yaml` en la imagen.

En el equipo de pruebas con Windows las mismas baterías de PHP pasan también con las compilaciones oficiales para Windows de PHP 8.1.34, 8.2.35, 8.3.33, 8.4.27 y 8.5.12 (x64, solo con la extensión `openssl` activada, `error_reporting=-1`), sin ningún aviso, notice ni deprecación; `php -l` pasa en todos los ficheros PHP con cada una.

## Entorno de referencia (Ubuntu 24.04)

```sh
apt install xrdp xorgxrdp openbox xterm freerdp2-shadow-x11 xvfb xclip xdotool imagemagick \
            pipewire-module-xrdp pipewire pipewire-pulse wireplumber pulseaudio-utils sox
```

- **xrdp** (TLS, licencias, portapapeles, unidad, audio, varios monitores): un usuario local; `~/.xsession` arranca PipeWire dentro de `dbus-run-session` y ejecuta `/usr/libexec/pipewire-module-xrdp/load_pw_modules.sh` para el audio. `/dev/fuse` debe tener permiso de escritura para la unidad y los archivos del portapapeles.
- **NLA**: `Xvfb :5`, `/etc/winpr/SAM` con `usuario::LMHASH:NTHASH:::` y `freerdp-shadow-cli /port:3390 /sec:nla`.
- **Seguridad RDP estándar**: xrdp con `security_layer=rdp`, uno por cada `crypt_level` (`low`, `medium`, `high`, `fips`), cada uno en su propio puerto, y el servidor FreeRDP.
- **Kerberos**: un KDC de MIT Kerberos con un reino de prueba, escuchando solo en 127.0.0.1: un usuario, servicios `HTTP/` y `TERMSRV/` en keytabs, y principales solo con claves RC4 (como en un dominio de Windows Server 2003); un aceptador de CredSSP hecho sobre el GSSAPI de MIT para NLA, y la puerta de enlace de código abierto para la RD Gateway.
- **Versiones de PHP**: 8.1, 8.2, 8.4 y 8.5 compiladas desde las etiquetas de `php-src` con `./configure --disable-all --with-openssl --enable-session` (así también se demuestra que no hace falta ninguna otra extensión); 8.3 de la distribución.
- **Servidor de desarrollo**: `PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8100 -t public` con un `config.php` cuyo `data_dir` apunte a una carpeta temporal.
- **Firefox**: Firefox y geckodriver de conda-forge, Selenium de PyPI.
- **Canal gráfico / H.264**: el FreeRDP de la distribución no trae H.264, así que se compila FreeRDP 3 con `-DWITH_OPENH264=ON` (`libopenh264-dev`). `freerdp-shadow-cli /port:3391 -auth /sec:tls` sobre una pantalla `Xvfb`; `-gfx-avc420`, `-gfx-progressive`, `-gfx-rfx` y `-gfx-planar` eligen los códecs. Los vectores de códecs se generaron con pequeños programas en C enlazados con esa biblioteca (sus codificadores y decodificadores).
