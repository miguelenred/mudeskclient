## Test suites

On GitHub, `.github/workflows/tests.yml` runs on every push and pull request, on Linux and Windows (no RDP server needed):

- `tests/run.php` and `tests/fuzz.php --strict` with PHP 8.1, 8.2, 8.3, 8.4 and 8.5; any PHP warning, notice or deprecation fails the run. One exception, said in the output: with PHP 8.1 there, PHP's built-in web server (a development server, used only by the tests) stops on the request that runs out of memory before any page is sent, so that page is not checkable there; it is checked with 8.2 to 8.5 there and with 8.1 on the Windows test computer.
- Every `tests/*_unit.mjs` and `tests/fuzz.mjs --strict` with the current and the previous Node.js LTS (Node.js 22 or later: the tests use the browser's global `navigator`, which Node has since version 21).
- The Docker image, built and started (Linux only): it answers over HTTPS with the setup screen, keeps the private folders out of reach, refuses a body over 8 MB and has no local files; then the same with Docker Compose (`compose.yaml`, its image built from that code): the setup screen, the setup code, the data volume, no `compose.yaml` in the image; both become *healthy* (`health.php` from inside), Compose with its logs rotated and `no-new-privileges`, and `MUDESK_WORKERS` is taken (300) or put back to 256 (5); the WebSocket service answers through Apache's `/ws` (101, and 403 to another site's page), the page is given its path, and `'websocket' => false` in a mounted `config.php` ends it (503, no path given).
- The Helm chart: `helm lint`, rendered as it comes and with every option, then installed in a `kind` cluster from the image of that code, its pod ready (`health.php`) and answering with the setup screen.
- `deploy/lxc/install.sh` on Ubuntu (systemd) and in Debian 12 without systemd: HTTPS with the setup screen, only `public/` served, plain HTTP sent to HTTPS, `--workers` taken, the WebSocket service answering through Apache (the systemd service `mudesk-ws`, as Apache's user, or started by the script without systemd; 403 to another site's page); run again, the data kept and the service answering.

`.github/workflows/fuzz.yml` fuzzes every night, and when started by hand (with a seed and a number of cases of your choice): `tests/fuzz.php --strict` with PHP 8.1 and 8.5 and `tests/fuzz.mjs --strict` with the current Node.js LTS, 10 000 cases per target for the gateway and 20 000 for the browser (about 50 times those of a push), with three new seeds each run (ten times the run's number, plus 1, 2 and 3; a push keeps seed 1, so it never fails on an input found by chance). A failure shows its input and the command that replays it in the run's summary and its log (kept 30 days). GitHub stops a schedule after 60 days without activity in the repository: it is started again from the Actions tab.

On the Windows test computer the same PHP suites also pass with the official Windows builds of PHP 8.1.34, 8.2.35, 8.3.33, 8.4.27 and 8.5.12 (x64, only the `openssl` extension enabled, `error_reporting=-1`), with no warning, notice or deprecation; `php -l` passes on every PHP file with each one.

## Reference environment (Ubuntu 24.04)

```sh
apt install xrdp xorgxrdp openbox xterm freerdp2-shadow-x11 xvfb xclip xdotool imagemagick \
            pipewire-module-xrdp pipewire pipewire-pulse wireplumber pulseaudio-utils sox
```

- **xrdp** (TLS, licensing exchange, clipboard, drive, audio, multi-monitor): a local user; `~/.xsession` starts PipeWire inside `dbus-run-session` and runs `/usr/libexec/pipewire-module-xrdp/load_pw_modules.sh` for audio. `/dev/fuse` must be writable for the drive and clipboard files.
- **NLA**: `Xvfb :5`, `/etc/winpr/SAM` with `user::LMHASH:NTHASH:::` and `freerdp-shadow-cli /port:3390 /sec:nla`.
- **Standard RDP Security**: xrdp with `security_layer=rdp`, one per `crypt_level` (`low`, `medium`, `high`, `fips`), each on a port of its own, and the FreeRDP server.
- **Kerberos**: an MIT Kerberos KDC with a test realm, listening on 127.0.0.1 only: a user, `HTTP/` and `TERMSRV/` services in keytabs, and principals with RC4 keys only (as in a Windows Server 2003 domain); a CredSSP acceptor built on MIT's GSSAPI for NLA, and the open-source gateway for the RD Gateway.
- **PHP versions**: 8.1, 8.2, 8.4 and 8.5 built from the `php-src` tags with `./configure --disable-all --with-openssl --enable-session` (this also proves that no other extension is needed); 8.3 from the distribution.
- **Development server**: `PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8100 -t public` with a `config.php` whose `data_dir` points to a temporary folder (and `'trusted_proxies' => ['127.0.0.1']` for `tests/auth_e2e.php`). The browser tests, signed in as an administrator, trust the test computer's certificate whenever its fingerprints are shown (for their own connection: *Valid for every user* is left unticked, as it comes).
- **Firefox**: Firefox and geckodriver from conda-forge, Selenium from PyPI.
- **Graphics pipeline / H.264**: the distribution's FreeRDP is built without H.264, so FreeRDP 3 is built from source with `-DWITH_OPENH264=ON` (`libopenh264-dev`). `freerdp-shadow-cli /port:3391 -auth /sec:tls` on an `Xvfb` display; `-gfx-avc420`, `-gfx-progressive`, `-gfx-rfx`, `-gfx-planar` choose the codecs. The codec vectors were produced with small C programs linked against the same library (its encoders and decoders).

## Windows 11 Pro (23H2, NLA)
