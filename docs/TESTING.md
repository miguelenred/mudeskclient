## Test suites

On GitHub, `.github/workflows/tests.yml` runs on every push and pull request, on Linux and Windows (no RDP server needed):

- `tests/run.php` and `tests/fuzz.php --strict` with PHP 8.1, 8.2, 8.3, 8.4 and 8.5; any PHP warning, notice or deprecation fails the run. One exception, said in the output: with PHP 8.1 there, PHP's built-in web server (a development server, used only by the tests) stops on the request that runs out of memory before any page is sent, so that page is not checkable there; it is checked with 8.2 to 8.5 there and with 8.1 on the Windows test computer.
- Every `tests/*_unit.mjs` and `tests/fuzz.mjs --strict` with the current and the previous Node.js LTS (Node.js 22 or later: the tests use the browser's global `navigator`, which Node has since version 21).

On the Windows test computer the same PHP suites also pass with the official Windows builds of PHP 8.1.34, 8.2.35, 8.3.33, 8.4.27 and 8.5.12 (x64, only the `openssl` extension enabled, `error_reporting=-1`), with no warning, notice or deprecation; `php -l` passes on every PHP file with each one.

## Reference environment (Ubuntu 24.04)

```sh
apt install xrdp xorgxrdp openbox xterm freerdp2-shadow-x11 xvfb xclip xdotool imagemagick \
            pipewire-module-xrdp pipewire pipewire-pulse wireplumber pulseaudio-utils sox
```

- **xrdp** (TLS, licensing exchange, clipboard, drive, audio, multi-monitor): a local user; `~/.xsession` starts PipeWire inside `dbus-run-session` and runs `/usr/libexec/pipewire-module-xrdp/load_pw_modules.sh` for audio. `/dev/fuse` must be writable for the drive and clipboard files.
- **NLA**: `Xvfb :5`, `/etc/winpr/SAM` with `user::LMHASH:NTHASH:::` and `freerdp-shadow-cli /port:3390 /sec:nla`.
- **PHP versions**: 8.1, 8.2, 8.4 and 8.5 built from the `php-src` tags with `./configure --disable-all --with-openssl --enable-session` (this also proves that no other extension is needed); 8.3 from the distribution.
- **Development server**: `PHP_CLI_SERVER_WORKERS=8 php -S 127.0.0.1:8100 -t public` with a `config.php` whose `data_dir` points to a temporary folder.
- **Firefox**: Firefox and geckodriver from conda-forge, Selenium from PyPI.
- **Graphics pipeline / H.264**: the distribution's FreeRDP is built without H.264, so FreeRDP 3 is built from source with `-DWITH_OPENH264=ON` (`libopenh264-dev`). `freerdp-shadow-cli /port:3391 -auth /sec:tls` on an `Xvfb` display; `-gfx-avc420`, `-gfx-progressive`, `-gfx-rfx`, `-gfx-planar` choose the codecs. The codec vectors were produced with small C programs linked against the same library (its encoders and decoders).

## Windows 11 Pro (23H2, NLA)

Server, gateway (PHP 8.3 for Windows; the session's input through a local TCP port, through the queue file in the tests before 1.0.0) and decoders on the same computer. PHP 8.1, 8.2, 8.4 and 8.5 are the official Windows builds, unpacked in a temporary folder (see the PHP versions row). PHP's development server on Windows serves one request at a time (no `PHP_CLI_SERVER_WORKERS`), so browser tests need a real web server or several `php -S` behind a proxy.

| Area | Result |
|---|---|
| Connection | NLA (CredSSP) over TLS 1.3; licensing: desktop Windows answers "valid client"; clear errors for a wrong password, "TLS only" (the server requires NLA) and "another user connected with this account" |
| Users | `user`, `.\user`, `HOST\user` and `OTHERDOMAIN\user` sign in; `user@HOST` is refused by Windows (local accounts have no UPN, as with the Windows client) |
| Keyboard and mouse | scancodes, clicks, wheel; bursts of Unicode text were mixed up by Windows 11 Notepad (the gateway sends one character every 100 ms and keeps the order; spaced in the browser, HTTP requests delivered some characters together).
